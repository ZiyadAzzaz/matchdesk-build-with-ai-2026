Understand a choice before confirming

matchdesk/static/app.js: renderGuide() / renderChoice() explains the first fictional payment and connects the selected invoices to their calculation, saved references and original records. matchdesk/review.py: Review.preview_impact() applies the real approval rules to a deep copy. POST /api/impact checks the current revision and returns consequences without changing reservations, history or revision. Sequence/version/selection checks discard late responses. After confirmation, the screen links to other payments whose actual status or count changed.

Add records without a file

static/app.js ? configureAddForm() presents the invoice/payment form. server.py ? POST /api/add applies revision checks and calls Review.add_record(). The existing parser validates values before appending a manual-origin row and creation event. Existing decisions and CSV hashes are preserved. Acknowledged POST /api/empty replaces the workspace and requires a fresh start.

To change this, start here

Layout, labels and controls

static/index.html and static/styles.css define the workspace. static/app.js → renderInspector() controls the decision panel. CSS media queries describe smaller layouts; they still require real viewport inspection.

CSV columns, monetary limits or matching scope

engine.py → read_table(), parse_rows(), money(), find_candidates(). Start with tests for a failing record or incorrect candidate before changing the parser. Keep original IDs as strings and do not silently skip rows.

HTTP session and concurrency behavior

server.py → create_app() isolates browser sessions and checks local mutation requests. Review.check_version() rejects stale changes. The process stores data in memory; restarts lose it.

A practice to reuse

Test a counterexample rather than only a successful demonstration. Here 200 equals both one invoice and a pair. tests/test_engine.py → test_actual_csv_has_real_ambiguity_and_unique_pair() verifies both alternatives; tests/frontend.test.mjs tests evidence, confirmation and undo through the real HTTP API. Specifying ambiguity before polishing controls prevents a confident-looking wrong answer.

Run it again

From the project folder: python -m matchdesk. Open http://127.0.0.1:8503, or double-click Start-MatchDesk.cmd after installing dependencies. Python tests: python -m pytest -q. Frontend tests: npm ci, then npm test with the intended Python active. This map needs no network or scripts. See README.md.
